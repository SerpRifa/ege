# 01 — Игровая механика

Единственный источник правил для очков, уровней, статусов, расписания, серии и ачивок. Все константы живут в `config/game.ts`; логика — чистые функции в `lib/game/`.

## Предметы

| id | Название (UI) | День обязательного занятия |
|----|---------------|----------------------------|
| `informatics` | Информатика | Понедельник |
| `math` | Математика (профиль) | Среда |
| `russian` | Русский язык | Четверг |

Дни недели: ISO (`1` = пн … `7` = вс). Часовой пояс приложения: **`Asia/Yekaterinburg` (UTC+5)**, константа `timezone` в конфиге. «Сегодня» всегда считается в этом поясе.

## Категории заданий и веса

| Категория | Вес (XP) |
|-----------|----------|
| A | 1 |
| B | 10 |
| C | 50 |

Формула одной записи:

```
xp(entry) = countA * 1 + countB * 10 + countC * 50
```

Ввод: неотрицательные целые. Хотя бы одно из A/B/C > 0 при сохранении.

## Уровни (нелинейно)

Для перехода с уровня `n` на `n+1` нужно:

```
xpToNext(n) = round(10 * n^1.5)
```

Пользователь начинает с **уровня 1** и **0 накопленных XP** на треке.

Накопленный XP до начала уровня `L` (для L ≥ 2):

```
cumulativeXpToReach(L) = sum_{n=1}^{L-1} xpToNext(n)
```

`cumulativeXpToReach(1) = 0`.

Функции:

- `levelFromXp(totalXp) → { level, xpIntoLevel, xpToNext, progress01 }`

Уровень **не ограничен сверху** формулой (можно расти дальше 15); статусы после Гигачада не добавляются, пока их нет в конфиге.

## Статусы

Одинаковая лестница для треков `informatics`, `math`, `russian` и `overall`. Порог — **минимальный уровень**, с которого статус активен. При равенстве уровней берётся статус с наибольшим `minLevel` среди достигнутых.

| id | Название | minLevel | Накопленный XP до этого уровня |
|----|----------|----------|--------------------------------|
| `botik` | Ботик | 1 | 0 |
| `nubik` | Нубик | 3 | 38 |
| `normis` | Нормис | 5 | 170 |
| `sharyashiy` | Шарящий | 7 | 429 |
| `tasher` | Тащер | 10 | 1110 |
| `sigma` | Сигма | 12 | 1791 |
| `gigachad` | Гигачад | 15 | 3200 |

### Трек предмета

`totalXp(subject) = sum xp(entry)` по всем записям этого предмета.

Статус и уровень предмета считаются из `totalXp(subject)`.

### Общий трек (`overall`)

```
totalXp(overall) = sum totalXp(subject) по трём предметам
```

Та же формула уровней и **та же таблица статусов** (v1).

Смысловая цель «общий Гигачад ≈ Гигачад во всех трёх» при одинаковых порогах наступает раньше (~3200 суммарных XP, а не ~9600). Это намеренное упрощение: общий трек даёт раннюю мотивацию, ачивка `all_gigachad` остаётся долгосрочной целью. Отдельные пороги для `overall` можно добавить в конфиг позже без смены схемы БД.

Названия статусов для отдельного предмета можно переопределить в конфиге (`statusOverrides[subject][statusId]`), картинки — всегда по `statusId`.

## Расписание и «занятие засчитано»

Обязательные слоты:

```
schedule = {
  1: 'informatics', // пн
  3: 'math',        // ср
  4: 'russian',     // чт
}
```

В любой день можно вносить запись по **любому** предмету; очки всегда засчитываются.

**Обязательное занятие засчитано**, если в календарный день `D` (в timezone приложения):

1. `D` — день из `schedule`;
2. предмет дня = `schedule[weekday(D)]`;
3. сумма XP записей **этого предмета за день D** ≥ `minSessionXp` (по умолчанию **10**).

Дополнительные занятия в другие дни / по другим предметам **не** продлевают и **не** ломают серию сами по себе.

## Серия (streak)

Серия — число **подряд** выполненных обязательных слотов в хронологическом порядке расписания (пн → ср → чт → пн → …), считая от самого свежего назад.

Правила:

1. Берём упорядоченный список прошедших обязательных дат до «сегодня» включительно (если сегодня обязательный день).
2. Идём с конца: каждый выполненный слот +1 к streak; первый невыполненный — стоп, streak = накопленное.
3. Если сегодня обязательный день и занятие ещё не выполнено — сегодняшний слот **не** считается пропуском до конца дня (streak не обнуляется заранее). После наступления следующего календарного дня невыполненный слот считается пропуском.
4. Пропуск обнуляет серию. **XP и уровни не уменьшаются.**

Пример: выполнены пн и ср, чт пропущен → streak = 0. Затем выполнен следующий пн → streak = 1.

Функция: `computeStreak(entries, today, config) → number`.

## Ачивки

Определения в `config/game.ts` как массив `{ id, title, description, check }`. Проверка — чистая функция от снимка прогресса. При сохранении записи сервер сравнивает состояние «до/после» и пишет новые id в `user_achievements` (идемпотентно).

Стартовый набор:

| id | Условие |
|----|---------|
| `first_session` | Есть хотя бы одна запись |
| `streak_3` | streak ≥ 3 |
| `streak_10` | streak ≥ 10 |
| `streak_30` | streak ≥ 30 |
| `perfect_week` | В одной календарной неделе (пн–вс) выполнены все три обязательных слота |
| `first_c` | Хотя бы одно задание C суммарно |
| `ten_c` | Сумма C ≥ 10 |
| `hundred_a` | Сумма A ≥ 100 |
| `extra_session` | Есть запись в день **не** из schedule **или** по предмету ≠ предмету дня schedule |
| `status_up` | Хотя бы раз сменился статус любого предметного трека (не overall) — фактически: текущий статус предмета ≠ `botik` |
| `subject_gigachad` | Хотя бы один предмет в статусе `gigachad` |
| `all_gigachad` | Все три предмета в статусе `gigachad` |

Ачивки не отзываются при пересчёте (односторонние).

## Оценка темпа (справочно, не код)

При ~100 XP за занятие до Гигачада предмета (~3200 XP) ≈ 32 занятия. Одних обязательных слотов до мая обычно мало — нужны доп. дни. Числа в конфиге правятся без смены кода.

## Примеры расчёта

1. Запись: A=5, B=2, C=1 → XP = 5 + 20 + 50 = **75**. С нуля: уровень 1 + 75 XP → проходит 10 (ур.2) + 28 (ур.3) = 38, остаток 37 из 52 → **уровень 3**, прогресс 37/52.
2. Статус при totalXp = 170 → уровень 5 → **Нормис**.
3. Статус при totalXp = 3199 → ещё не 3200 → уровень 14 → **Сигма**; при 3200 → уровень 15 → **Гигачад**.

## Критерии приёмки

- [ ] `config/game.ts` содержит веса, `xpToNext`, статусы, schedule, `minSessionXp`, timezone, список ачивок.
- [ ] Юнит-тесты: `xp`, `xpToNext`, `levelFromXp`, `statusFromLevel`, `computeStreak`, примеры из раздела выше.
- [ ] Пропуск обязательного слота обнуляет streak и не меняет XP.
- [ ] Доп. занятие в «свободный» день даёт XP и может открыть `extra_session`, не ломая streak.
